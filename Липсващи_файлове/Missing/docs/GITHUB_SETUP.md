# GitHub Project и Issues
Подготвени са 20 описания в issues/. Номерата 01–20 са локални идентификатори, а не реални GitHub номера. Няма създадени от този пакет remote ресурси.

## Настройка
1. Създайте repository TimeTravel-Quest и добавете съученика като collaborator.
2. Качете README.md и docs/. Останалата структура се допълва при разработката: src/, tests/, database/schema.sql, presentation/, LICENSE, .gitignore и .env.example.
3. Създайте Project с колони Backlog, Ready, In progress, Review, Done.
4. Добавете полета Role, Week, Priority и Effort. Роли A+B означава двама участници, но за всяка задача изберете един водещ отговорник.
5. Създайте Issues от файловете в docs/issues/; добавете ги в Project и задайте истинските assignees. CSV файлът е удобен преглед, не автоматичен GitHub import.
6. Създайте milestones „Седмица 1“ до „Седмица 5“. Заменете локалните зависимости с линкове към реалните Issues.
7. Задачи 01–05 са за първата седмица. Отбележете Done само след собствен преглед и реално изпълнение. Останалите започват в Backlog.

## Общи правила
Една основна задача In progress на човек. При блокиране запишете причината и зависимостта. Свързвайте PR с Issue. И двамата правят собствени commits; не се измисля история на принос.

Критичен път: концепция → ER/интерфейс → Auth и данни → първа мисия → запис и инвентар → алгоритми и пет глави → тестове → публикуване.

За всяка промяна използвайте кратък branch, например feature/inventory. Не публикувайте secrets. Преди финалното предаване README трябва да има истинските repository и demo URLs; не замествайте липсващи адреси с измислени.

## Допълнителни изисквания от Classroom
Всеки участник прави поне един собствен commit още през Седмица 1. Подходяща действителна промяна е преглед и корекция на определен документ или макет. Не правете празни commits само за бройка и не използвайте чужда самоличност. Авторът свързва commit URL в своя раздел на WEEK_1_REPORT.md.

Примерно разпределение за първите 12 Issues: A води 01, 03, 06, 09, 10 и 12; B води 02, 04, 05, 07, 08 и 11. Общото участие остава възможно. Това е предложение, не реално назначение в GitHub. Използвайте собствените си профили като assignees.

За отчет и финален преглед добавете отделни checklist задачи към Issue 05: попълнен README с двама участници; два лични commits; два лични отчета; проверени Classroom линкове. Новият минимум е шест Issues, но запазваме минимум 12 по специфичното задание.
